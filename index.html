What Is Grasshopper?

Grasshopper is a visual programming language embedded inside Rhinoceros 3D. Instead of writing lines of code, you connect components on a canvas — building data-driven logic that generates and controls geometry in real time.

Every definition is a graph: inputs flow left, outputs flow right, and the Rhino viewport updates instantly as you adjust any parameter.

Why It Matters for Designers

  • Change one parameter and the entire model rebuilds
  • Encode rules and relationships, not just geometry
  • Explore thousands of design variations rapidly
  • Automate repetitive modeling tasks
  • Bridge design intent and fabrication data
  • Foundation for advanced scripting (Python / C#)
01 · What It Is

Visual Algorithm Editor

Design Through Parameters

Assignment · Week 03

Pseudocode Flowchart
Twisted Tower

Base Shape: Ellipse Deliverable: Flowchart diagram Format: Digital or hand-drawn

Brief

Write the pseudocode and draw a complete flowchart for a Twisted Tower definition in Grasshopper. The base of the tower is an ellipse (not a rectangle).

Your diagram must show all inputs, the floor loop logic, the per-floor transformations (move + rotate), the loft operation, and the final output. Do not open Grasshopper yet — work only in pseudocode and diagram form.

Parameters to Define

  • →ellipse_radius_x — major axis of the base ellipse
  • →ellipse_radius_y — minor axis of the base ellipse
  • →floor_count — number of floors
  • →total_height — full tower height
  • →twist_angle — total degrees of rotation over height
  • →base_plane — origin plane for the ellipse

Reference Pseudocode — Ellipse Base

// PSEUDOCODE — Twisted Tower with Ellipse Base BEGIN TwistedTower_Ellipse INPUT: ellipse_radius_x = 8 // major axis (X) ellipse_radius_y = 5 // minor axis (Y) floor_count = 20 total_height = 60 twist_angle = 90 // degrees total rotation base_plane = WorldXY // Step 1 — Create base ellipse on the base plane base_curve = Ellipse( plane=base_plane, radius_x=ellipse_radius_x, radius_y=ellipse_radius_y ) // Step 2 — Calculate per-floor increments floor_height = total_height / floor_count angle_per_floor = twist_angle / floor_count // Step 3 — Loop: generate one ellipse curve per floor FOR each floor_index IN Range( 0, floor_count ): elevation = floor_index * floor_height rotation = floor_index * angle_per_floor moved_curve = Move( base_curve, vector = Z * elevation ) rotated_curve= Rotate( moved_curve, angle = rotation, axis = Z ) Append( floor_curves, rotated_curve ) END FOR // Step 4 — Loft all floor ellipses into a surface tower_surface = Loft( floor_curves ) OUTPUT: tower_surface END

Your Diagram Must Include

  • ✓ START and END terminators
  • ✓ INPUT parallelogram with all 6 parameters
  • ✓ Create Ellipse process box
  • ✓ Decision diamond: index < floor_count?
  • ✓ Move + Rotate process boxes inside the loop
  • ✓ Loop-back arrow with "NO → loop" label
  • ✓ Loft process box after loop exits
  • ✓ OUTPUT parallelogram: tower_surface

Key Difference from Rectangle Base

Using an ellipse instead of a rectangle means your base curve creation step requires two radius inputs instead of width/height — but the loop logic (Move → Rotate → Append) remains identical.

Note that radius_x ≠ radius_y creates an asymmetric twist — the rotation will be more visually pronounced along the minor axis.

Your pseudocode must explicitly name both radii as separate inputs.

Flowchart Notation Reference

What Is a Pseudocode Diagram?

A pseudocode diagram (flowchart) is a visual representation of a process — the logic made visible. It maps every decision, action, and data flow using standardized shapes connected by directed arrows. Unlike written code, it is language-agnostic and readable by anyone.

A recipe is the perfect starting structure: it has ingredients (inputs), steps (processes), conditional judgments ("if not done, continue"), and a finished dish (output).

Core Concepts to Master

  • Every process has exactly one START and one END
  • Shapes carry specific semantic meaning — don't improvise
  • Arrows show direction and control flow, never reversed arbitrarily
  • Decisions always branch into exactly two paths: YES and NO
  • All paths must eventually reconnect or reach END
  • Loops require a re-entry arrow pointing backward
  • Keep each box to one atomic action or decision
01
Vocabulary

Shape Reference — What Each Box Means

Each shape in a flowchart is a symbol with a specific, non-negotiable meaning. Using the correct shape is as important as using the correct notation in architectural drawing.

START / END
Oval / Terminator
"Begin: Gather your mise en place"

Marks the single entry point (START) and all exit points (END) of the algorithm.

PROCESS
Rectangle / Process
"Dice the onion into 5mm cubes"

Any action, calculation, or transformation. One verb, one object per box.

YES/NO ?
Diamond / Decision
"Is the sauce reduced by half?"

A binary question with exactly two exits: YES and NO.

INPUT / OUTPUT
Parallelogram / I/O
"Add 2 cups of flour" / "Serve the dish"

Data entering or leaving the system.

SUB-PROCESS
Rounded Rectangle
"Make the roux" (a whole sub-recipe)

A predefined sub-process — a named block of steps defined elsewhere.

CALLED PROCESS
Rectangle with Ears
"Refer to base stock recipe"

A call to an external procedure. Control leaves and returns.

COLOR ASSIGNMENTS: Start / End Process Decision Input / Output Sub-Process
02
Connectors

Arrow Types — How to Connect Boxes

Arrows are not decoration — they encode direction, condition, and flow priority. Every arrow must be directed (have an arrowhead).

Standard Flow Arrow

Default connector. Solid line, single arrowhead. Flows top to bottom or left to right.

"Heat pan → Add oil → Add onions"

Y
N
Decision Branch — YES / NO

Always label both exits from a diamond. Label near the arrowhead.

"Is pasta al dente? Y → drain / N → continue"

Dashed / Conditional Arrow

Optional path. Use when a step may occur but isn't part of the main flow.

"Optionally: add truffle oil before serving"

Loop-Back Arrow

Returns flow to a previous step. Always drawn outside the main flow column.

"Taste → Adjust seasoning → Taste again"

Arrow Routing RulesAll primary flow goes top-to-bottom or left-to-right. Loop-back arrows travel along the outside edge. When arrows must cross, draw a bridge arc. Label every decision arrow and every loop-back condition.
03
Method

Step-by-Step: Recipe → Pseudocode Diagram

We will convert a simple pasta recipe into a complete flowchart. Follow each step before moving to the next.

1

Read the Entire Recipe First — Identify All Actions

Annotate every verb — each is a potential process node. Underline conditionals ("if", "until", "while") — those become diamonds.

// EXAMPLE RECIPE — Spaghetti Aglio e Olio 1. Boil salted water 2. Cook spaghetti until al dente ← DECISION 3. Meanwhile, slice garlic thin 4. Toast garlic in olive oil until golden ← DECISION 5. Add chili flakes 6. Reserve pasta water 7. Drain pasta 8. Toss pasta with oil + water 9. Taste → adjust salt ← DECISION 10. Plate and serve

Result: 7 process nodes, 3 decision diamonds, 2 parallel tracks.

2

Write the Pseudocode in Plain Language

Convert your annotated recipe into structured pseudocode using indentation to show nesting.

BEGIN SpaghetttiAglioeOlio INPUT: spaghetti, garlic, olive_oil, chili, salt boilWater(salt) cookPasta(spaghetti) WHILE pasta.texture != "al dente" DO continueCooking(pasta) END WHILE sliceGarlic() toastInOil(garlic, olive_oil) WHILE garlic.color != "golden" DO continueToasting(garlic) END WHILE addChiliFlakes() reservePastaWater() drainPasta() toss(pasta, oil_mixture, pasta_water) taste() IF seasoning != "balanced" THEN adjustSalt() END IF OUTPUT: plate(dish) END
3

Sketch the Skeleton — Start with START and END

Place START oval at top center, END oval at bottom. Draw a vertical spine connecting them.

Spatial RuleLeave at least 1.5× the height of your largest box between nodes. Cramped diagrams are unreadable.
4

Place Process Boxes — One Action Per Box

Write text in the imperative mood. Never write more than one action per rectangle.

Text Rule3–7 words per box, action-first. Never passive voice. Bad: "The water is boiled." Good: "Boil salted water."
5

Insert Decision Diamonds at Each Conditional

Every WHILE / IF / UNTIL becomes a diamond. YES goes down (main flow); NO goes to a loop-back.

DIAMOND: "Al dente?" YES → continue to drain pasta NO → loop back to "Continue cooking"
6

Draw Parallel Tracks for Simultaneous Processes

Split into two columns using a horizontal bar and rejoin before the next shared step.

// SPLIT at: "While pasta cooks..." [horizontal fork bar] LEFT: cookPasta → [Al dente?] → drain RIGHT: sliceGarlic → toastInOil → [Golden?] → addChili [horizontal join bar]
7

Add Input / Output Parallelograms

Parallelogram after START declares all inputs. Another near END marks the final output.

8

Label All Arrows — Review Every Connection

Every arrow needs an arrowhead. Every diamond exit must be labeled YES/NO. Trace every path to END.

Final ChecklistOne START and one END · Correct shape types · Every arrow directed · Every diamond has two labeled exits · All loops have a termination condition · No dead ends · Parallel tracks merge before END

Quality Control

Visual Design Rules — Do's and Don'ts

A flowchart is a communication tool. These principles separate a legible professional diagram from a confusing one.

ElementDOAVOID
Box SizeKeep all process boxes the same width.Varying box widths arbitrarily.
AlignmentCenter-align all boxes on a single vertical axis.Scattering boxes with no structural grid.
Arrow LengthKeep arrows short. Long arrows signal poor layout.Crossing arrows without a bridge arc.
TextOne consistent typeface. Sentence case. 3–7 words per box.Full sentences, passive voice, unexplained abbreviations.
ColorAssign color by shape type. Max 4–5 colors with a legend.Random or decorative color use.
Loop RoutingRoute loop-back arrows along the outer edge, same side.Loop-back arrows crossing primary flow.
DensityLeave 1–2× box-height of white space between nodes.Compressing to fit a page.
Decision LabelsLabel both exits of every diamond near the arrowhead.Unlabeled exits or labels at the diamond body.
